# 환경과 디자인 검증

검증일: 2026-11-11. Apple Silicon Mac, Pleos Connect 2.1.0 / Android API 34 기준입니다.

## 로컬 검증

- Java 17 / Gradle 8.10.2로 assembleDebug와 lintDebug 통과, Lint 오류 0건
- 앱 설치와 최종 대시보드 실행
- 실제 좌석 점유, 등받이 위치, 열선, 앞좌석 통풍, 공유 풍량, 공조 전원 조회 성공
- 현재 이미지에서 뒷좌석 통풍은 미지원으로 표시
- 온도 capability의 구역은 조회되지만 현재 온도 값은 확인 불가로 반환되어 화면에서도 확인 불가로 표시
- 실제 데이터와 디자인 미리보기 전환
- 조수석 선택 시 하단 자세 정보가 해당 예시 위치값 34로 변경
- 음악/라디오 예시 탭 전환
- 스타일 가이드 진입과 복귀, 2560x1440 차량 화면에서 배치 확인

현재 폴링은 화면 활성 상태에서 조회 완료 후 약 2초 간격으로 수행합니다. 실제 차량 제어와 음원 재생은 포함하지 않습니다. 로고는 제공된 이미지 초안을 개발용 벡터로 재구성한 버전입니다.

## 에뮬레이터 제어 연결 수정

문제 원인: 공식 콘솔 세션이 없으면 DDS 중계가 비활성 상태여서 OS 조작의 결과가 돌아오지 않았습니다. debug 앱이 로컬 세션을 유지하도록 수정했습니다.

- 공식 콘솔 브라우저를 닫은 뒤에도 MORI의 활성 세션과 중계가 유지됨을 확인
- 온도 24.5/23 → 22.5/23.5, 풍량 4 → 2 변경이 SDK와 MORI 화면 모델에 반영됨
- 운전석 열선 1 → 2, 조수석 통풍 2 → 1이 실제 SDK 응답으로 반영됨
- 음수 seat-temperature 값을 통풍으로 변환하는 회귀 검사 4건 통과
- 내기순환 상태가 SDK와 화면 모드에 반영됨
- 시트 자세 37/54는 공식 시뮬레이터의 실시간 위치값으로 반영. SDK는 여전히 0을 반환하여 자세(시뮬) 출처를 표시
- debug 빌드, Android Lint, 단위 검사, release 빌드 통과
- 당시 release APK에 로컬 세션/제어 endpoint 문자열과 debug cleartext 설정이 포함되지 않는 것을 확인. 후속 프로필 개편은 공통 로직에 제어 경로 문자열이 있으나 HTTP 클라이언트/세션과 cleartext 설정은 계속 debug 전용

[최종 반영 화면](images/control-sync.png), [조작 방법과 지원 범위](EMULATOR_CONTROLS.md)

온도 확인 불가와 read-only 화면만 제공하던 위 초기 상태는 이번 수정 이전의 기록입니다.

## 두 탭과 프로필 개편 / 2026-11-11

이 절이 현재 상태이며 위의 스타일 가이드/음악 탭/읽기 전용 초기 기록은 이전 구현입니다.

- 공통 기능/개별 좌석 탭, 오른쪽 프로필 목록과 생성/수정/상세 구현
- 스타일 가이드 진입과 하단 음성 영역 제거
- 88dp 탭과 80dp 이상 주요 버튼, 주야간 팔레트, 1000dp 기준 가로/세로 배치
- 단위 검사 8건: 열선/통풍 정규화 4건과 프로필 미지원 값/변경 비교/반영 확인 4건
- 에뮬레이터 통합 검사: 프로필 저장 후 재로딩, 중복 없이 수정, 삭제, 앞뒤32/등받이41/높이58 실시간 적용 확인, 공조24℃/풍량3 SDK 재조회 확인, 미디어 선호 선택
- 검사는 임시 프로필을 사용하며 종료 시 기존 프로필 목록과 좌석/공조 설정 복원
- 1700x1184 기본 화면, 1256x800/648x800 제약과 프로필 편집, 야간 팔레트 렌더링

통합 검사는 새 의존성 없이 Android Instrumentation을 사용합니다. `:app:assembleDebugAndroidTest`로 빌드한 후 Pleos 에뮬레이터에서 `com.cheonsaeun.mori.test/com.cheonsaeun.mori.ProfileInstrumentation`을 실행합니다. 실제 시뮬레이터 제어가 포함되므로 주차 상태의 개발용 에뮬레이터에서 실행합니다.

모든 화면 비율의 물리적 가독성, 차량 주행 제한, 음원 재생은 이번 검사에 포함되지 않았습니다.

## 통합 차량 상태 화면 / 2026-11-12

- 두 탭을 좌석 60% / 공조/미디어 40% 화면으로 통합하고 프로필 관리를 별도 설정창으로 이동
- 좌석별 탑승자 변경, 게스트 전환, 새 프로필 생성과 기존 프로필 덮어쓰기, 저장 설정 복원
- 공통 목록의 실제 탑승 우선 정렬과 관계 필터, 관계 필드의 이전 자료 호환
- 가족 예시의 프로필/차량 설정을 메모리에 격리하고 실제 상태 복귀
- 단위 검사 총 13건: 기존 8건과 목록 정렬/관계 필터, 중복 배정, 하차 처리, 공조 일치, 초기 게스트 5건

화면과 자세한 자체 UX 검토는 [통합 대시보드 사용법](PROFILE_DASHBOARD.md)에 기록합니다. 이전 두 탭 검증 화면은 개편 전 기록입니다.

- debug/release 빌드와 Android Lint 통과, 단위 검사 13건 실패 0건
- 실제 에뮬레이터 좌석 3축과 공조 온도/풍량 적용 및 재조회 검증 유지
- 실제 Compose UI 동작 검사: 프로필 관리 열기, 친구 필터, 탑승자 변경, 게스트 선택, 새 프로필 이름 입력/저장, 작성 취소 확인 후 내용 유지
- 예시에서 직접 바꾼 등받이36을 아빠 프로필에 덮어쓰기, 등받이42로 재조정 후 저장 설정36으로 복원 확인
- 공조 취향 선택은 확인 전 상태가 유지되고 확인 후에만 반영되는지 검사
- 관계 저장/재로딩, 같은 프로필의 중복 좌석 방지, 예시 저장소 분리와 실제 데이터 복원 검사
- 1700x1184 기본 앱 영역, 1256x800/648x800 제약, 야간 테마와 큰 설정창 화면 기록
- 테스트 종료 시 임시 프로필을 제거하고 원래 좌석/공조와 프로필 목록을 복원

차량 OS의 기본 접근성 트리에서 앱의 임베디드 창이 제외되어 통합 검사는 앱의 공개 Compose semantics 액션과 WindowInspector의 프로세스 내부 창 목록을 사용합니다. 별도 UI 테스트 의존성이나 시스템 설정 변경 없이 실행합니다. 이 어댑터는 androidTest에만 포함됩니다.
