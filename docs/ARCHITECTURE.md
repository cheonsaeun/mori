# 구조와 연동 원칙

## 현재 코드

- `MainActivity`: Android 앱 진입점
- `ui/MoriApp`: Compose 시작 화면
- `ui/MoriViewModel`: 조회 상태, 실패, 타임아웃 관리
- `vehicle/VehicleGateway`: Pleos API 호출과 자원 해제

화면은 Vehicle SDK를 직접 호출하지 않습니다. 향후 공조와 좌석 조회는 gateway를 기능별로 확장합니다. 현재 gateway는 읽기 전용입니다. NaviHelper는 의존성만 연결되어 있으며 경로 요청은 아직 실행하지 않습니다.

## 음성 기능을 연결할 때

Pleos 앱에서 마이크 입력 → 음성 AI 서버 → 구조화된 요청 → 앱의 프로필/조율 로직 → 사용자 확인 → 지원되는 차량 API 실행 → 결과 안내 흐름으로 확장합니다. 음성 모델과 Gleo가 동일한 앱 기능을 호출하도록 입력 경로를 분리합니다. 모델이 반환한 문장을 실행 성공의 증거로 쓰지 않습니다.

## 차량 기능

- 기능마다 capability, 영역, 접근 수준, 허용 값을 확인합니다.
- 좌석과 공조 구역의 대응은 실제 반환 정보와 검증한 차량 구성으로 결정합니다.
- 확인받은 준비안만 실행하고 결과를 다시 읽습니다.
- 수동 변경을 반복해서 덮어쓰지 않습니다.
- 실제 SDK, 모의 차량 상태, 사용자 입력의 출처를 개발 기록에 구분합니다.
- 주행 관련 화면 제한은 CarUxRestrictionsManager를 연결해 처리할 예정입니다. 현재 앱은 주차 상태에서 사용하는 시작 앱입니다.

## 개인정보와 외부 서비스

이번 이동의 요청과 장기 저장 선호를 구분합니다. 저장 동의, 수정, 삭제는 프로필 구현 단계에 포함합니다. API 키는 서버의 환경 변수에서 관리하고 앱에는 넣지 않습니다. 서버 주소와 공개 설정의 예시는 공유할 수 있지만, 실제 인증 정보와 설문 원본, 응답자 연락처는 공유하지 않습니다.
