# 구조와 연동 원칙

## 현재 코드

- `design/MoriTheme`: 색상, 글꼴, 간격, 모양, 모션 토큰
- `design/MoriComponents`: 패널, 배지, 심볼, 상태 지표
- `ui/MoriApp`: 공통 기능/개별 좌석 탭과 반응형 배치
- `ui/SeatMap`, `ui/SharedSpace`: 개별 좌석과 공통 공간
- `ui/MoriViewModel`: 실제 데이터/미리보기, 프로필 저장/적용, 결과 재조회
- `ui/preview/PreviewSnapshot`: 명시적 디자인 예시 데이터
- `model/VehicleSnapshot`: 값과 지원 상태를 분리한 화면 모델
- `vehicle/VehicleGateway`: capability 조회, 상태 조회, 자원 해제

화면 활성 상태에서만 조회 루프를 실행합니다. 콜백을 코루틴으로 변환하며, 각 요청은 1.8초 제한을 둡니다. 취소된 요청은 뒤늦은 응답을 화면에 반영하지 않습니다. 지원 영역은 기능별로 캐시하고 조회 실패 시에는 다시 확인합니다. 대시보드의 SDK 호출은 읽기 전용입니다. debug의 EmulatorSession과 EmulatorControls는 공식 에뮬레이터 세션 유지와 제어를 담당하며 release에서는 동작하지 않습니다. 좌석 앞뒤/등받이/높이와 점유 상태는 별도의 시뮬레이터 실시간 신호로 보완합니다. NaviHelper는 의존성만 연결되어 있습니다.

## 음성 기능을 연결할 때

Pleos 앱에서 마이크 입력 → 음성 AI 서버 → 구조화된 요청 → 앱의 프로필/조율 로직 → 사용자 확인 → 지원되는 차량 API 실행 → 결과 안내 흐름으로 확장합니다. 음성 모델과 Gleo가 동일한 앱 기능을 호출하도록 입력 경로를 분리합니다. 모델이 반환한 문장을 실행 성공의 증거로 쓰지 않습니다.

## 차량 기능

- 기능마다 capability, 영역, 접근 수준, 허용 값을 확인합니다.
- 좌석과 공조 구역의 대응은 실제 반환 정보와 검증한 차량 구성으로 결정합니다.
- 확인받은 준비안만 실행하고 결과를 다시 읽습니다.
- 수동 변경을 반복해서 덮어쓰지 않습니다.
- 실제 SDK, 모의 차량 상태, 사용자 입력의 출처를 개발 기록에 구분합니다.
- 주행 관련 화면 제한은 CarUxRestrictionsManager를 연결해 처리할 예정입니다. 현재 앱은 주차 상태에서 사용하는 시작 앱입니다.

## 개인정보와 외부 서비스

이번 이동의 요청과 장기 저장 선호를 구분합니다. 프로필 생성/수정 시 동의한 선호를 기기 내부에 저장하고 삭제 기능을 제공합니다. 프로필은 SharedPreferences JSON으로 저장하며 저장 실패를 표시합니다. 좌석 연결은 메모리에만 유지합니다. API 키는 서버의 환경 변수에서 관리하고 앱에는 넣지 않습니다. 서버 주소와 공개 설정의 예시는 공유할 수 있지만, 실제 인증 정보와 설문 원본, 응답자 연락처는 공유하지 않습니다.

프로필 모델은 `model/PersonProfile`, 저장은 `model/ProfileStore`, 편집 화면은 `ui/ProfilePane`에 있습니다. 설정 적용은 코루틴으로 처리하며 즉시 진행 상태를 표시합니다. 실시간 조회는 Mutex로 직렬화하고 적용 후 최대 8회 재조회하여 확인합니다. 이 단계의 공조 선호는 온도와 풍량이며 모드별 선호나 여러 사람 간 조율은 포함하지 않습니다.
